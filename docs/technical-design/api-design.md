## 2. API 设计

### 2.1 通用约定

后台接口前缀为 `/api/admin/v1`。

- JSON 请求与响应使用 UTF-8。
- 时间采用 ISO 8601 UTC 字符串。
- 列表返回 `items、nextCursor`。
- 普通响应返回业务数据和服务端生成的 `requestId`。
- 修改可编辑资源时携带读取时的 `revision`。
- 创建、签发及发布等命令携带 `Idempotency-Key`。
- 客户端不能指定公司归属、操作者或执行身份。
- 返回对象使用专门的 DTO，不直接返回 Prisma 实体或秘密密文。
- 下表的 HTTP 状态码为成功状态；失败统一按 2.3 节处理。

补充约束：

- 后台没有“代员工批准并执行业务”的接口。
- `resolve` 只记录核查结论，不执行 OA、不触发重试。
- 取消只允许作用于 `PENDING`，不能撤回已领取或已发出的请求。
- 未批准执行范围的草稿只能校验、预览。
- 真实调试须绑定管理员批准的配置范围，不能由实施人员将草稿标为“查询”就绕过人工确认。
- 同一去重键对应不同参数时返回 `409`。
- 凭据签发响应丢失后，同键查询只返回“已签发”和凭据 ID；管理员显式吊销后，用新操作重新签发。

### 2.3 错误处理方案

统一错误字段：

| 字段 | 含义 |
|---|---|
| `code` | 稳定的机器错误码 |
| `message` | 可向用户展示的说明 |
| `requestId` | 服务端追踪编号 |
| `fieldErrors` | 可选，字段级校验错误 |
| `operationStatus` | 可选，未执行、成功、明确失败、结果未知等状态 |

| HTTP 状态码 | 使用场景 |
|---|---|
| `400` | JSON 格式、请求结构或游标格式错误 |
| `401` | 未登录、会话失效或 MCP 凭据无效 |
| `403` | 已识别身份但无操作权限 |
| `404` | 资源不存在或当前身份不可见 |
| `409` | 编辑版本冲突、唯一性冲突、去重键异参、状态冲突 |
| `413` | 请求体超过限制 |
| `422` | 字段、映射或发布配置校验失败 |
| `429` | 超过调用频率或并发限制 |
| `502` | 上游接口或响应处理异常 |
| `503` | 数据库、必要审计或依赖服务不可用 |
| `504` | 执行阶段超时 |

错误不得包含密钥、Token、验证码、内部堆栈或未过滤的上游响应。

**HTTP 错误码不等于业务执行结论。** 非查询请求已经发出后发生超时、断连、响应过大或解析失败，没有可靠证据时必须返回“结果未知”。

### 2.4 MCP 接口

MCP 使用独立入口 `/mcp`，采用 HTTPS Streamable HTTP。

| 请求 | 处理 |
|---|---|
| `POST /mcp` | 承载 `initialize`、协议通知、`tools/list`、`tools/call` 等 JSON-RPC 消息 |
| `GET /mcp` | 启用并验证兼容性后提供 SSE；未启用时按协议返回 `405` |
| 传输会话关闭 | 若启用有状态会话，按协议处理；关闭连接不等于吊销凭据或撤销业务 |

MCP 使用员工个人 `Authorization: Bearer …`，后台 Cookie 不作为 MCP 凭据。每次请求重新检查员工、凭据及相关资源状态。

协议结构错误与工具执行错误分别处理；工具参数、上游业务等执行错误使用 MCP 工具结果表达，必要时设置 `isError: true`，不套用后台 REST 响应外壳。[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

工具发现规则：

- 只返回当前员工获授权、已发布且启用的工具。
- 不返回未授权工具的名称、描述或参数。
- 非查询执行门禁未通过时，不将其作为可执行工具开放。
- 工具列表支持分页；实际客户端工具规模和分页兼容性需要联调验证。

查询调用直接执行受控请求并返回结果。非查询调用只生成待确认记录和预览，不在此阶段调用业务接口。

可提供保留名称的只读状态工具，用于查询本人操作记录；读取业务结果时仍检查当前权限。**不提供模型可调用的“传验证码立即执行”工具。**

### 2.5 鉴权方式与系统调用

后台鉴权使用服务端会话：

- Cookie 设置 `Secure、HttpOnly、SameSite=Strict、Path=/`，不设置宽泛 Domain。
- 写请求验证来源和会话绑定的 CSRF Token。
- 改密、停用和退出时吊销对应会话。

业务系统调用流程：

1. 识别平台员工及获授权工具。
2. 读取已发布配置和有效人员绑定。
3. 将公司固定信息及当前人员字段映射到受控鉴权请求。
4. 按真实 OA 协议获得可用鉴权状态。
5. 构造业务请求，使用固定执行身份调用。
6. 校验、映射并过滤返回数据，记录结果。

OA Token 缓存键至少包含公司、系统、员工绑定、配置版本和凭据修订号。相关配置变化后缓存失效；缓存不能替代实时权限检查。

业务请求发出后，即使收到 Token 失效错误，也不能刷新 Token 后自动重放该业务请求。
